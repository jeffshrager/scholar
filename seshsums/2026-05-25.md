# Session 2026-05-25

## What existed at start

A stub `scholar.py` using old Selenium API (`find_element_by_xpath`) with a hardcoded GS user ID (`weAbyM4AAAAJ`). No database, no reporting, no persistence.

## What happened

Built a two-script citation tracking system from scratch:

**scholar.py** (scraper/updater):
- Switched from Selenium to Playwright with system Chrome (`channel="chrome"`) + stealth JS patches (`navigator.webdriver = undefined`) to avoid GS bot detection
- Scrapes GS author profile, expands full paper list, then fetches all citing papers for each paper
- Saves to `scholar_db.json` after each paper — crash/block-safe
- Incremental updates: skips papers whose citation count hasn't changed AND whose `citations_complete` flag is True
- `citations_complete` flag added after GS cut off the first run mid-way — ensures incomplete papers are resumed, not skipped
- `--full` flag to force re-scrape; `--headless` to suppress browser window (default is visible for CAPTCHA solving)

**report.py** (offline reporter):
- `python report.py` — stats table: all 78 papers, GS count vs. DB count, completeness flag
- `python report.py --since YEAR` — citing papers published in YEAR or later, grouped by your paper

**Key bug found and fixed**: GS uses `\xa0` (non-breaking space) around the hyphen separator in author/venue/year info lines. Splitting on `" - "` silently failed, dumping the entire info line into the `authors` field and leaving `year` blank. Fixed in `_parse_info_line` and repaired existing DB records via migration script.

**GS rate-limiting**: GS blocked us mid-scrape after many CAPTCHAs. A lingering background `scholar.py` process kept overwriting the DB, undoing the repair — had to kill it before the fix stuck.
